# Мои тренировки

Бесплатный личный дневник тренировок для iPhone. Быстрая запись отдельных подходов, история, графики и отчёты для ChatGPT. Интерфейс на русском, светлая и тёмная темы. Работает как устанавливаемое PWA.

Все записи находятся в IndexedDB на вашем устройстве. В приложении нет сервера, регистрации, аналитических трекеров, внешних API, платных функций или облачной синхронизации. Сайт передаёт браузеру только файлы приложения; записи не отправляются на хостинг. Отчёт отправляется куда-либо только через выбранное вами действие «Поделиться» или вручную после копирования.

## Быстрый запуск на компьютере

Нужны Node.js 22 или новее и npm. Для установки зависимостей нужен интернет.

```sh
npm ci
npm run dev
```

Откройте адрес, напечатанный Vite в терминале (обычно http://localhost:5173).

Для проверки именно готовой PWA:

```sh
npm run build
npm run preview
```

Откройте напечатанный адрес localhost. В режиме `dev` service worker намеренно выключен; офлайн проверяется на production-сборке. Двойное нажатие на `dist/index.html` не запускает PWA: необходим HTTP-сервер, а вне localhost — HTTPS.

## Как проверить на iPhone

1. Самый простой вариант — разместить приложение на GitHub Pages по инструкции ниже.
2. Откройте HTTPS-адрес сайта в Safari на iPhone. Во встроенном браузере мессенджера установка может быть недоступна.
3. Дождитесь полной первой загрузки. В настройках приложения нажмите «Установить на iPhone»: после подготовки появится сообщение о готовности офлайн.
4. Создайте тестовую тренировку, добавьте упражнения и подходы, закройте и снова откройте дневник.
5. Проверьте запись подходов при открытой клавиатуре, портретный режим и смену темы.

Для локального просмотра интерфейса можно открыть сетевой адрес Vite с iPhone в той же Wi-Fi сети. Но обычный HTTP-адрес компьютера не даёт полноценного service worker; для проверки PWA используйте HTTPS-хостинг. Данные localhost, сетевого адреса и опубликованного сайта — разные базы.

## Бесплатная публикация на GitHub Pages

1. Создайте на GitHub бесплатный публичный репозиторий, например `moi-trenirovki`.
2. Загрузите исходники, включая скрытую папку `.github`, `package.json` и `package-lock.json`. Не загружайте `node_modules`, `work`, резервные копии и личные отчёты. Данных ваших тренировок в исходниках нет.
3. Используйте основную ветку `main`.
4. В репозитории откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**.
5. В **Actions** запустите workflow **Publish to GitHub Pages**, либо сделайте push в `main`.
6. Дождитесь зелёной отметки. Ссылка появится в задании `deploy` и в Settings → Pages. Типичный адрес: `https://ВАШ-ЛОГИН.github.io/moi-trenirovki/`.

Workflow выполняет `npm ci`, тесты и сборку, затем публикует только `dist`. Он автоматически задаёт `BASE_PATH` по имени репозитория. Для корневого репозитория `ВАШ-ЛОГИН.github.io` или собственного домена измените `BASE_PATH` в workflow на `/`.

Ручная сборка для подпапки:

```sh
# macOS / Linux
BASE_PATH=/moi-trenirovki/ npm run build

# PowerShell
$env:BASE_PATH = '/moi-trenirovki/'
npm run build
```

Значение обязательно начинается и заканчивается `/`. Для корня сайта `BASE_PATH=/`. В приложении нет маршрутов, требующих серверного роутера: разделы переключаются внутри одной страницы. Ресурсы, manifest и регистрация service worker учитывают подпапку.

`.openai/hosting.json` относится только к дополнительному размещению через Sites; GitHub Pages его не использует. При самостоятельном копировании проекта можно удалить `.openai`.

## Как добавить на главный экран iPhone

1. Откройте сайт в Safari.
2. Нажмите системную кнопку **«Поделиться»**.
3. Выберите **«На экран Домой»**.
4. Подтвердите **«Добавить»**.
5. Запустите приложение с нового значка и дождитесь загрузки.

Приложение учитывает Safe Area и нижнюю системную область. В полях веса и повторений размер шрифта не менее 16 px, используется цифровая клавиатура; масштабирование страницы не запрещается.

## Ежедневная запись

- Нажмите **«Начать тренировку»** или выберите готовый шаблон.
- Нажмите **«Добавить упражнение»**, найдите название. Можно добавить несколько упражнений подряд, затем нажать «Готово».
- Впишите вес и повторы прямо в строке. Для дробного веса подойдут `12,5` и `12.5`.
- **Рб** — рабочий подход, **Р** — разминка. Нажатие переключает тип.
- Отметьте выполненный подход галочкой. Пустые повторы и незаполненный вес не позволяют отметить подход выполненным.
- **«Добавить подход»** копирует вес, повторы и тип предыдущего, оставляя выполнение выключенным. В меню `…` есть копирование, перемещение и удаление строки.
- Меню упражнения позволяет изменить порядок или убрать его из тренировки.
- Поля сохраняются автоматически после каждого изменения. Индикатор сверху показывает незавершённую запись. Дождитесь её завершения перед принудительным закрытием браузера.
- При возвращении на главную черновик доступен через **«Продолжить тренировку»**. Одновременно хранится один черновик, повторное нажатие старта не создаёт дубль.
- **«Завершить тренировку»** фиксирует дату и время окончания; их можно изменить перед подтверждением. Для перехода через полночь задайте следующую дату.
- Ненужный черновик можно удалить с подтверждением внизу редактора.

В истории есть календарь, фильтр дат, просмотр, явный переход к редактированию и повторение. В просмотре можно сохранить запись как шаблон. Повторение не меняет исходную запись и не отмечает новые подходы выполненными.

## Прогресс

Периоды: 7, 30, 90 дней, год, вся история и собственный интервал. Расчёты используют только завершённые тренировки.

- Рабочий объём = сумма `вес × повторы` выполненных рабочих подходов с внешним отягощением.
- Разминка и невыполненные подходы исключены из основной нагрузки.
- Собственный вес считается отдельно по повторам и подходам, упражнения на время — по секундам.
- Для выбранного упражнения отображаются даты, максимальный рабочий вес, повторы, максимальный объём за тренировку и три графика.
- `e1RM = вес × (1 + повторы / 30)`. Учитываются только выполненные рабочие подходы на 1–10 повторений с внешним отягощением. Это расчётная оценка, а не проверенный максимум.
- Нет двух подходящих тренировок — нет графика или процента, который создавал бы ложное впечатление точности.
- Суммарный объём разных упражнений показывает количество нагрузки, а не силу. Сравнение при завершении выводится для одинакового набора упражнений и поясняется как изменение объёма.

Для гантелей выберите удобное правило записи (одна гантель или сумма) и применяйте его последовательно: программа не пересчитывает вес автоматически.

## Экспорт для ChatGPT

Кнопка **«Скопировать для ChatGPT»** расположена на главной и в настройках.

Выберите последнюю тренировку, 30/90 дней, всю историю, собственный интервал или одно упражнение. Доступны:

- Читаемый текст с упражнениями, подходами, заметками и точными итогами.
- JSON с идентификаторами, датами, весами, повторами и отметками выполнения.
- Копирование (Clipboard API с резервным способом), системное «Поделиться» и скачивание.

При экспорте одного упражнения показатели нагрузки относятся к нему, длительность — к тренировкам целиком; это подписано в отчёте. JSON отчёта предназначен для анализа, он не является полной резервной копией. Для переноса всей базы используйте следующий раздел.

## Резервные копии

1. Откройте **Настройки → Резервная копия → Скачать резервную копию**.
2. Убедитесь, что файл `мои-тренировки-ДАТА.backup.json` появился в загрузках или в приложении «Файлы».
3. Сохраните его вне браузера: например, в выбранной вами папке iCloud Drive, на компьютере или внешнем диске.
4. Делайте копию регулярно и обязательно перед переустановкой, сменой браузера, адреса сайта или очисткой данных.

Копия содержит каталог (включая архив), тренировки и черновик, снимки упражнений, все подходы, шаблоны и настройки. Дата последней копии означает момент запуска скачивания: браузер не позволяет проверить факт сохранения файла.

### Восстановление

1. Установите/откройте приложение по нужному адресу.
2. При необходимости сначала скачайте копию текущей базы.
3. В настройках нажмите **«Восстановить из копии»** и выберите JSON.
4. Программа проверит версию, значения, уникальность идентификаторов и связи между таблицами.
5. После проверки увидите число тренировок и упражнений. Нажмите **«Заменить базу и восстановить»**.

Импорт заменяет всю текущую базу, без объединения и частичного добавления. Замена выполняется одной транзакцией IndexedDB: при ошибке исходная база остаётся целой. Поддерживается формат версии 1, размер входного файла — до 50 МБ. CSV в настройках служит для таблиц и анализа, не для восстановления.

## Офлайн и обновления

После первой полной загрузки production-версии service worker сохраняет HTML, скрипты, стили, manifest и значки. Внешние шрифты и ресурсы не используются. Проверьте готовность: включите авиарежим, полностью закройте приложение и откройте его с главного экрана.

Новая версия предлагается баннером **«Обновить»**. Обновление меняет файлы приложения и кэш, не удаляя IndexedDB. Номер схемы Dexie — 1; будущие изменения структуры должны добавляться миграцией, а не удалением базы.

iOS может очищать данные сайтов, особенно при недостатке места. Удаление сайта или PWA может удалить записи. Запрос постоянного хранения в настройках зависит от браузера и не заменяет резервные копии. Между устройствами автоматической синхронизации нет.

Таймер хранит абсолютное время окончания и пересчитывается при возвращении. Интервалы: 60, 90, 120, 180 секунд или собственное значение до 3600 секунд. В фоне на iOS звуковое уведомление не гарантируется; push-уведомлений нет.

## Архитектура

- React 19 + TypeScript + Vite.
- Dexie / IndexedDB: `workouts`, `exercises`, `workoutExercises`, `sets`, `templates`, `settings`.
- `workoutExercises` хранит снимок названия, категории и типа нагрузки. Переименование каталога не меняет историю. Используемые упражнения архивируются вместо удаления связей.
- Recharts: динамика веса, объёма и e1RM.
- Zod: проверка входной резервной копии.
- vite-plugin-pwa / Workbox: precache и офлайн-навигация с поддержкой подпапки.
- UUID для сущностей, транзакции для связанных изменений. Одна тренировка-черновик.
- `src/stats.ts` — расчёты; `src/db.ts` — хранение; `src/backup.ts` — копии; `src/export.ts` — отчёты.

## Проверки

```sh
npm test
npm run build
node scripts/check-build.mjs dist /
BASE_PATH=/moi-trenirovki/ npm run build -- --outDir work/subpath-dist
node scripts/check-build.mjs work/subpath-dist /moi-trenirovki/
```

Автоматические тесты используют Vitest, fake-indexeddb и React Testing Library. Синтетические записи находятся только в тестах, история пользователя при запуске пуста.

Проверяются расчёты, e1RM и исключение разминки; переход через полночь; сериализация и точность JSON; некорректные и повреждённые копии; откат транзакции при сбое записи; закрытие и повторное открытие базы; защита от дублей; повторение с невыполненными подходами; сохранность снимков при переименовании; каскадное удаление; текст/JSON/CSV; пять упражнений, быстрый ввод дробного веса, правки и завершение; создание пользовательского упражнения; порядок шаблонов; разделы приложения, смена темы и продолжение черновика.

`check-build.mjs` проверяет ссылки на ресурсы, scope/start_url, состав precache, fallback и путь регистрации SW для корня и подпапки. Это статическая проверка, а не запуск браузера без сети.

Результаты выполненных проверок и оставшиеся ручные проверки — в `ПРОВЕРКИ.md`.

## Известные ограничения

- В данной среде недоступен инструмент браузерного управления. Реальный Safari на iPhone, экранная клавиатура, установка PWA, авиарежим и обновление установленной версии требуют ручной проверки на устройстве.
- Сохранность IndexedDB зависит от политики и свободного места браузера; резервная копия нужна даже установленной PWA.
- Частный адрес Sites может требовать входа на уровне хостинга. Самостоятельная публикация на GitHub Pages даёт обычный HTTPS-сайт без регистрации в приложении.
- Нет автоматической синхронизации, фоновых уведомлений, медицинских рекомендаций или автоматического импорта чужих форматов.
- Интерфейс хранит один активный черновик. Встроенных ограничений на число исторических записей нет; фактический объём ограничен хранилищем устройства.
